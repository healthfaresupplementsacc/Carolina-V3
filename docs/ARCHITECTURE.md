Walmart shipments arrive with cost 0 and empty service (their own labels): stored, counted separately, never in an average or median. The alert wording is now HONEST — proven on 8/8 recent outliers the paid rate was ALREADY the cheapest valid one, and Bruno objected "e se nao tiver opcao?": a cheaper valid quote (margin $0.25) says "Cotei agora: tem X por $Y" and only THEN advises delete-and-rebuy; a quote with no cheaper option says "ja era o melhor preco valido disponivel. Grouped alerts carry a per-line suffix (`| cotei: da $X (svc)` / `| ja era o melhor` / `| sem cotacao`) and the closing delete-and-rebuy line appears only when at least one line has a cheaper option; the digest gains "K com opcao mais barata (da pra recuperar $X)" when K>0. Every rates failure returns `null` — quoting is advisory and can NEVER break the tick. Nothing buys, prints or cancels in Fase A.

## 2. Tasks (events)

Operator task lifecycle: start/end/join/retroactive, cowork, pauses, machine handoff. Table `v3.events`.

**Owning files**
- `src/routes/op.js` — operator page HTTP routes: start `:1568` (solo insert `:1766`, cowork inserts `:1717-1732`), retroactive `:1798`, finish-preview `:1959`, end `:2020` (close UPDATE `:2126`), join `:2332`, reclassify `:3070`, machine custody `:2285`.
- `src/v3/services/EventService.js` — documented single write-door for `v3.events` from Slack/Observer/admin (`:5-21`): `upsert` `:542`, `closeActivePersonEvent` `:427`, `safetyAutoClose` `:681`, `_syncCowork` `:364`.
- `src/v3/pause/service.js` (2026-08-19) — **the pause clock, for the whole group**. Routes `/api/v3/op/pause/pending|answer|join`, plus `freezeActiveFor`/`resumePausedFor` inside `op.js` which now delegate here. Born from event 3583: Vitor opened a `break` 11:18:36 → 12:43:07 with Bruno Sarmento in the cowork; Vitor's own event froze correctly (`total_paused_seconds` = 5071, exactly the break) while Bruno Sarmento's review (#3575, 09:50 → 13:05) kept running at 0 — an hour and a half of pause counted as work. Three real holes: the freeze ran once for the *starter* even though the cowork insert loop creates one event per participant; `resumePausedFor(personId)` un-froze one person, so colleagues stayed frozen forever and never got the "continuar ou finalizar?" prompt; and attaching someone to a running pause from the admin dashboard had no pause logic at all. `freezeFor(personIds, exceptEventIds, {creditSeconds})` and `resumeFor(personIds)` now take the whole participant list (`participantsOf` unions the `cowork_group_id` members **and** the `cowork_with[]` array — reading only one of the two is what left Bruno Sarmento out); `endPauseFor(pauseEventId)` un-freezes the group and returns the resumed tasks **per person**, so each kiosk asks its own owner. **The question** (Bruno, 2026-08-19): someone joining a pause already in progress is asked "Você estava nisso desde o começo?" with two options — `inicio` credits from the pause's `started_at`, `agora` from the moment they joined — and the answer is stored on their own pause event (`joined_since`/`joined_at`/`join_assumed`, migration 076) so the timeline and the admin can see which it was. **Rule #0**: when the person is not at the kiosk (the exact 3583 case) nothing waits for them — the pause event is created with `joined_since` NULL, the conservative `agora` applies immediately, and the question surfaces at the top of `/op` the next time they touch the screen, saying in plain Portuguese what was assumed; answering `inicio` later *corrects* the numbers rather than refusing. `repairPauseOverlap({pause_event_id, apply})` is the historical repair: it measures the real intersection of each participant's events with the pause window, subtracts what is already in `total_paused_seconds`, and is a dry-run report unless `apply:true` — it never *removes* a discount (`would_add` is floored at 0) and is safe to run twice. **Writes only the clock** (`paused_at`, `total_paused_seconds`) and the three join columns; it never closes an event (`ended_at` stays with `op.js`) and never touches stock.
- **IMPORTANT:** `op.js` writes `v3.events` with **raw SQL, bypassing EventService** (`:1725,1766,2126`). The "single write-door" invariant in `EventService.js:5` is NOT enforced against the operator page. (See BROKEN LINKS.)

   - **Guard reality:** most closers include `WHERE ended_at IS NULL` (attendance-sync `:339,548,564`; CommandHandler `:783,798`; op.js bulk closers), which makes a concurrent double-close a no-op. Split the rest:
     - **Genuinely unguarded** (close by id / `ANY(ids)` with NO `ended_at IS NULL` on the UPDATE): `op.js:1662,1669,1680`.
